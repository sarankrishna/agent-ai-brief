## Three signals that should change your mental model

### 1. Agent security is becoming an operating-system boundary, not just a prompt policy

Microsoft made Execution Containers generally available. Developers specify files, network destinations, process settings, UI access, and containment level in policy outside the agent workload. The design spans process, session, WSL, and experimental MicroVM backends.

Architectural consequence: treat agents as untrusted workloads with independently enforced authority boundaries. Identity and enterprise management are separate control planes.

Primary source: [Microsoft Execution Containers](https://blogs.windows.com/windowsdeveloper/2026/10/07/microsoft-execution-containers-policy-driven-containment-for-ai-agents/)

### 2. Long-horizon agent performance is a state-management problem

Stateless Language Agents report that durable research state should live in a harness, while each invocation receives fresh, role-specific context. Explicit assignments and isolated worker contexts compound over long runs.

Architectural consequence: separate durable state, context construction, task assignment, execution, and evaluation. Conversation replay is not scalable memory.

Primary source: [Stateless Language Agents](https://arxiv.org/html/2610.07625)

### 3. Local AI stacks are converging on common application surfaces

Windows ML accepts GGUF and ONNX through task APIs, exposes an OpenAI-compatible local endpoint, and composes CPU, GPU, and NPU stages. Android is establishing a hardware-isolated vault for personal context and future in-vault inference.

Architectural consequence: portable interfaces above, explicit device placement, compilation, isolation, and residency controls below.

Primary sources: [Windows ML](https://devblogs.microsoft.com/foundry-on-windows/build-on-winml-oct-7-26/) and [Android AISeal](https://blog.google/security/enabling-the-next-gen-enclave-architecture-for-on-device-ai-on-android/)

## Architecture patterns emerging

### 1. Policy outside the agent, state outside the conversation

- **Evidence:** MXC keeps authority in OS policy; SLA keeps durable research state in the harness.

- **Implication:** Design agents as replaceable policy-constrained workers over explicit state stores, assignment queues, and evaluators.

- **Architect’s question:** Which state is durable, who can mutate it, and which component independently enforces authority?


### 2. Portable control surfaces over heterogeneous execution backends

- **Evidence:** Windows ML presents common model APIs over CPU, GPU, and NPU; MXC presents common policy over multiple backends; AISeal separates protected services from host execution.

- **Implication:** Keep application contracts stable while making placement, compilation, isolation, and policy backend explicit.

- **Architect’s question:** Can a workload move between backends without silently changing security, latency, or residency?


### 3. Closed-loop systems are replacing isolated AI tasks

- **Evidence:** Azure workflows connect planning, logistics, telemetry, prediction, and recovery. SLA connects state, assignment, execution, measurement, and iteration.

- **Implication:** Optimize the complete decision loop and feedback quality, not the apparent intelligence of one step.

- **Architect’s question:** What outcome is measured after action, and how does that evidence improve the next decision safely?

### Stateless Language Agents

- **Why read:** Concrete architecture for scaling automated research beyond context replay and short benchmarks.

- **Inspect:** Harness-owned state, Advisor-to-Worker assignments, context reconstruction, worker isolation, and matched-budget ablations.

- **Code/data/reproduction:** Implementation repository linked by the paper; reproduce with equivalent task and budget controls.

### VERSE: Verified Self-Evolving Optimizer for Agent Harnesses

- **Why read:** Shows why self-improvement requires execution-based verification and regression testing.

- **Inspect:** Trace minimization, replay, perturbation, training audits, and the outer self-evolution loop.

- **Code/data/reproduction:** Code is available at [wzekai/VERSE](https://github.com/wzekai/VERSE); results cover SWE-rebench and out-of-distribution tasks.

- **Link:** [Paper](https://arxiv.org/html/2610.02616)


### Bolmo and the byteifying recipe

- **Why read:** Tests whether representation changes can be retrofitted onto capable models instead of requiring full retraining.

- **Inspect:** Conversion stages, byte hierarchy, multilingual and rare-string behavior, serving cost, and parity against source models.

- **Code/data/reproduction:** Ai2 states checkpoints and recipe are open; independent reproduction remains needed.

- **Link:** [Ai2 announcement](https://allenai.org/blog/bolmo-nature)


### Windows ML and MXC as local-agent primitives

- **Why read:** Together they expose model loading, execution selection, composition, and resource containment.

- **Inspect:** GGUF and ONNX parity, local serving, deterministic pipelines, policy enforcement, denied-action behavior, and audit integration.

- **Code/data/reproduction:** Microsoft links documentation, samples, SDKs, and experimental APIs. Production suitability requires target-device testing.

- **Links:** [Windows ML](https://devblogs.microsoft.com/foundry-on-windows/build-on-winml-oct-7-26/) and [MXC](https://blogs.windows.com/windowsdeveloper/2026/10/07/microsoft-execution-containers-policy-driven-containment-for-ai-agents/)
