## Three signals that should change your mental model

### 1. Open models are becoming complete work systems

Tencent Hy4 preview combines a very large MoE model, a million-token-plus context window, application integration, and an iterative preview loop. The important unit is no longer only the checkpoint. It is the model, serving path, application harness, and feedback loop together.

**Architectural consequence:** Evaluate models inside the workflow and serving topology that will carry them. A benchmark result without latency, tool-call, context, and operating-cost measurements is insufficient.

**Primary source:** https://www.tencent.com/tencent-releases-and-open-sources-tencent-hy4-preview/

### 2. Agent platforms are becoming asynchronous operating surfaces

OpenAI ChatGPT Work release notes describe tasks triggered by changes in Gmail, Slack, and GitHub, with consequential actions paused for approval. This is a shift from request-response chat toward event-triggered, long-running work with explicit human control points.

**Architectural consequence:** Treat event intake, durable state, approval checkpoints, retries, and audit records as first-class platform components.

**Primary source:** https://help.openai.com/en/articles/6825453-chatgpt-release-notes

### 3. Self-optimization claims need a stronger evidence boundary

Tencent says Hy4 participated in optimizing training methods, evaluation, low-level operators, and its inference system, including a reported 31.8% end-to-end throughput improvement. These are technically important claims, but the public announcement does not provide enough experimental detail to establish repeatability or generality.

**Architectural consequence:** Separate bounded model-assisted optimization from general recursive self-improvement. Require released code, baselines, workloads, and independent checks before changing platform assumptions.

**Primary source:** https://www.tencent.com/tencent-releases-and-open-sources-tencent-hy4-preview/

- **Type:** Model release and application-integrated preview
- **Evidence:** Tier 1, Tencent announcement opened and checked
- **Maturity:** Preview. The announcement gives model size, active parameters, context length, app/API availability, an internal blind evaluation, and pricing.
- **Why it matters:** The 770B total / 49B active design and context window above one million tokens target long software-engineering and analytical workflows while keeping per-token activation below the total model footprint.
- **Architecture read:** This is a distributed inference problem, not a workstation model. Key questions are expert routing, KV-cache and context management, prefill/decode balance, tool-loop control, and the cost of retaining long context.
- **What is not proven:** Tencent reports a 2.99/4.00 internal score and 31.8% throughput improvement, but the announcement lacks enough public methodology, workload traces, hardware configuration, or independent results to validate those figures.
- **Decision:** Track
- **Source:** https://www.tencent.com/tencent-releases-and-open-sources-tencent-hy4-preview/

### 2. ChatGPT Work adds webhook-triggered scheduled tasks and shared task definitions

- **Type:** Agent platform capability update
- **Evidence:** Tier 1, OpenAI release notes dated August 25, 2026, opened and checked

## Research and implementation worth your time

### AgentSysBench: From LLM Inference to Agentic Workloads

- **Why read:** It frames agent serving as a cross-stack scheduling problem. The abstract reports non-LLM components dominating latency in 5 of 10 applications, sandbox working-set memory peaking at 28 GB per session, and shifting bottlenecks.
- **Inspect:** Task-aware scheduling, communication-aware placement, state offloading, and tool-result caching. The reported design explorations claim 29-40% latency reduction, up to 4.5x placement improvement, 4.6x lower memory use, and 19.3% aggregate search-latency savings.
- **Code/data/repeatability:** The paper says AgentSysBench will be released as open source. Confirm repository and artifact availability before planning a repeat.
- **Source:** https://arxiv.org/html/2608.15127

### Tencent Hy4 preview artifacts and serving path

- **Why read:** The release is a useful case study in coupling a large MoE, long context, application feedback, and serving optimization.
- **Inspect:** The exact model repository, license, quantization formats, API behavior, context truncation, tool-call protocol, and independently measured throughput.
- **Code/data/repeatability:** Tencent announcement links to app/API access but does not itself provide a complete repeatability package. Treat model artifacts and deployment support as requiring separate verification.
- **Source:** https://www.tencent.com/tencent-releases-and-open-sources-tencent-hy4-preview/

### ChatGPT Work scheduled-task model

- **Why read:** Event-triggered agents expose the reliability and governance concerns that ordinary chat APIs hide.
- **Inspect:** Trigger deduplication, state durability, approval expiry, action idempotency, connector permissions, audit export, and failure recovery.
- **Code/data/repeatability:** Closed capability. No public implementation or repeatable deployment was identified in the checked source.
- **Source:** https://help.openai.com/en/articles/6825453-chatgpt-release-notes
