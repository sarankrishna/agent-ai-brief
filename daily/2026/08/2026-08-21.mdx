## Three signals that should change your mental model

- **RAG is becoming evidence navigation.** Mistral exposes search, open, navigate, read, and grep as an agent loop over long documents. The design consequence is explicit evidence state, not only top-k chunks. [Mistral](https://mistral.ai/news/agentic-search)

- **Multimodal agents are judged by artifacts and loops.** Meta describes visual inputs, tool use, artifact re-checking, and a preview set of WildArtifactBench tasks. [Meta](https://research.meta.ai/blog/multimodal-intelligence-of-muse-spark-1-2)

## Ranked technical developments

### 1. Mistral Agentic Search
- **Type:** Retrieval tooling release, 20 Aug 2026.
- **Evidence:** Opened primary Mistral page. It reports FinanceBench and OfficeQA Pro results for search loops with document navigation.
- **Maturity:** Available through Search Toolkit and Libraries; figures are vendor-reported.
- **Why it matters:** The page reports GLM-5.2 at 51.9% on OfficeQA Pro with the full loop, 45.6 points above one-shot RAG, plus lower token use and latency in the stated tests.
- **Architecture read:** Keep the index, but add typed navigation tools, provenance, traversal budgets, and replayable evidence state.
- **What is not proven:** Private-corpus transfer, adversarial-document resilience, multilingual behaviour, and tail latency.
- **Decision:** Experiment
- **Source:** [Mistral](https://mistral.ai/news/agentic-search)

### 2. Meta Muse Spark 1.2 multimodal agent workflows
- **Type:** Multimodal model and workflow update, 20 Aug 2026.
- **Evidence:** Opened primary Meta page. It describes visual coding, audio-visual understanding, tool use, a two-level robotics design, and 10 preview tasks from WildArtifactBench.
- **Maturity:** Available in Meta Model API and Muse Code; the benchmark is an internal preview.
- **Why it matters:** Output quality becomes an artifact property. The harness must observe, act, render, and validate.
- **Architecture read:** Separate perception, planning, tool execution, artifact checks, and low-level actuation. Preserve the artifact and its evaluation evidence.
- **What is not proven:** Independent results, full benchmark release, and live reliability.
- **Decision:** Track
- **Source:** [Meta AI Research](https://research.meta.ai/blog/multimodal-intelligence-of-muse-spark-1-2)

### 3. ORBITER conflict-aware agentic decisions
- **Type:** New research submission, arXiv v1 dated 19 Aug 2026.
- **Evidence:** Opened paper. It combines heterogeneous proposers, a disagreement report, targeted tools, hypothesis verification, and an independent critic. It reports up to 9.2% average gain across four cities.
- **Maturity:** Research prototype.
- **Why it matters:** Expensive reasoning is reserved for conflicts rather than spent on every candidate.
- **Architecture read:** Use cheap rankers to bound choices, invoke deeper reasoning on disagreement, and retain evidence plus rejected alternatives.
- **What is not proven:** Live cost, latency, shift, tool corruption, and transfer beyond delivery data.
- **Decision:** Read deeply
- **Source:** [arXiv](https://arxiv.org/html/2608.18846)

### 4. Google CEL formal verification framework
- **Type:** Open-source policy verification release, listed in the August 2026 Google Open Source Blog index.
- **Evidence:** Opened primary page. It describes Z3-backed equivalence and validity checks, policy invariants, counterexamples, bounded checking, and explicit inconclusive results for unknown functions.
- **Maturity:** Available framework; integration maturity remains to be assessed.
- **Why it matters:** Generated policy changes need stronger assurance than example tests.
- **Architecture read:** Gate policy changes with parse, semantic modelling, proof, counterexample, and fail-closed handling outside the model context.
- **What is not proven:** Full CEL extension coverage, solver cost, and assurance for the surrounding enforcement system.
- **Decision:** Experiment
- **Source:** [Google Open Source Blog](https://opensource.googleblog.com/2026/08/securing-the-agentic-era-introducing-formal-verification-for-cel.html)

## Architecture patterns emerging

### Evidence-directed loops
- **Evidence:** Mistral navigation and ORBITER verification both select the next step from current evidence.
- **Implication:** Record the unresolved question, tool result, source location, and stopping rule at each step.
- **Architect question:** Which loop steps are deterministic and replayable?

### Artifact validation inside execution
- **Evidence:** Meta re-checks visual artifacts; ORBITER has an independent critic and evidence record.
- **Implication:** Validate outputs after tool execution instead of trusting the final model message.
- **Architect question:** What is the authoritative validator, and does it fail closed?
