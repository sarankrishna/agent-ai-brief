## Three signals that should change your mental model

### Agent production readiness is being defined by identity, evidence and bounded actions
AWS is adding OIDC, on-behalf-of identity and stored session replay to WorkSpaces for AI agents. This shifts the deployment question from “can the model operate the UI?” to “can every action be attributed, constrained and reviewed?” For enterprise architecture, treat identity propagation and replayable evidence as runtime primitives, not afterthoughts. [AWS announcement](https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-workspaces-AI-agents-connect-govern/)

### Science-agent claims are becoming a stack, not a model demo
NVIDIA packages an open model, chemistry dataset, post-training recipes and evaluation examples; AMD describes an HPC assistant connected to site-specific knowledge, job tooling and profiling. The differentiator is increasingly the integration path from domain data to governed tools and executable work, while vendor-reported task metrics still need independent reproduction. [NVIDIA](https://nvidianews.nvidia.com/news/nvidia-introduces-nemotron-for-science-to-accelerate-discoveries-with-agents) · [AMD](https://www.amd.com/en/blogs/2026/amd-brings-agentic-ai-to-supercomputing-with-open-source-amd-hpc.html)

### AI-assisted vulnerability discovery is changing disclosure operations
Anthropic is moving its own disclosure targets to 30 days for high/critical issues and 45 days otherwise, starting 2027-01-01, while keeping a 7-day window for active exploitation. This is a policy response to faster discovery and rediscovery, not evidence that every maintainer can patch on that cadence. Security programs should review triage capacity, owner escalation and safe release coordination. [Anthropic policy](https://www.anthropic.com/research/coordinated-vulnerability-disclosure-timelines)

- **Type:** Product capability / agent runtime
- **Evidence:** Primary vendor announcement, dated 2026-11-16.
- **Maturity:** Announced as available capabilities; validate regional/account availability and prerequisites in service documentation.
- **Why it matters:** OIDC IdP support, on-behalf-of sign-in, and session replay strengthen attribution and retrospective review for computer-using agents.
- **Architecture read:** Run agents within a managed desktop boundary, bind sessions to a human identity and existing directory policy, then retain replay evidence in customer-controlled S3 with customer keys. Confirm how delegated access, revocation, and evidence retention interact.

## Architecture patterns emerging

- **Agents are being attached to operational identity and evidence.** AWS session identity/replay and OpenAI assessor access protocols both emphasize attributable access and review. **Implication:** Design identity propagation, audit evidence, and data-access boundaries into the agent runtime. **Architect’s question:** Can operators reconstruct what an agent saw, on whose authority it acted, and what changed?
- **Domain grounding is moving into workflow integrations.** AMD connects to a site knowledge base and HPC operations; NVIDIA bundles domain data/evaluation with an adaptable model; ngrok brings current service docs and a policy validator into tool use. **Implication:** Durable usefulness depends on fresh, governed context and verifiable tool results. **Architect’s question:** Which actions can be executed safely from retrieved context, and where is independent validation required?

## Research and implementation worth your time

### Evolving Infra: Agent-Adaptive LLM Serving at Scale
- **Why read:** The paper argues that agent workload composition shifts prefill/decode balance and context management makes ordinary recency-based KV eviction unreliable.
- **Inspect:** Its separation of compute allocation from KV management, online PD-split planning, and agent-branch-aware KV retention. It reports up to 4.1× lower mean end-to-end latency and 14× lower P95 TTFT versus Dynamo on its tested workloads.
- **Code/data/reproduction:** Authors link an implementation at [MIT HAN Lab / EvolvingInfra](https://github.com/mit-han-lab/EvolvingInfra). The arXiv page describes experiments across GLM-5.2/Kimi K2.6 and up to 256 GB300 GPUs; independently reproduce on representative traces before using the reported speedups for capacity planning.
- **Source:** [arXiv paper](https://arxiv.org/abs/2611.12304)
