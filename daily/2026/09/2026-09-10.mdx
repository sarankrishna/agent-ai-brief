## Three signals that should change your mental model

### 1. Agent security is becoming a separate enforcement plane

Meta describes Muse as an agent running in an isolated cloud VM, with a host-side Sentinel controlling connector actions and network egress. The design includes scoped connector workers, credential surrogation, egress checks, SSRF controls, and tainted-egress approval logic.

**Why it matters:** Prompt-injection resilience is shifting from model behaviour to capability architecture.

**Architectural consequence:** Treat the model as an untrusted planner. Put credentials, approvals, egress, audit, and durable state behind independently enforced boundaries.

**Primary source:** https://research.meta.ai/blog/security-and-safety-for-ai-agents-our-approach-with-muse

### 2. Agent serving is a state-management problem

vLLM reports that AgentX traces contain long sessions, median 142K-token inputs, short outputs, more than 96 percent prefix-cache hit rate, and substantial subagent branching.

**Why it matters:** Conventional request-level load balancing can reduce performance by destroying cache locality.

**Architectural consequence:** Make session identity, cache residency, turn number, and likely branching visible to the serving scheduler. Benchmark end-to-end interactivity, not isolated tokens per second.

**Primary source:** https://vllm.ai/blog/2026-09-08-vllm-agentx

### 3. Production frameworks are converging on resumability and explicit consent

Google ADK for Kotlin 1.0 combines hierarchical agents, context compaction, resumable sessions, generated type-safe tools, and human confirmation flows across server-side Kotlin and Android.

**Why it matters:** Agent state and approval are becoming first-class application concerns rather than prompt conventions.

**Architectural consequence:** Design workflows as durable state machines with typed tools, explicit approval transitions, and recoverable execution.

**Primary source:** https://developers.googleblog.com/announcing-adk-for-kotlin-10-building-production-ready-ai-agents-in-kotlin-android-and-beyond/

## Architecture patterns emerging

### 1. Independent policy and capability planes for agents
- **Evidence:** Meta Sentinel and privileged services; GitHub managed sandbox policy; Red Hat gateway-level tool controls.
- **Implication:** Put authorization, egress, credentials, and runtime boundaries outside the model context. Bind approvals to exact capabilities.
- **Architect's question:** Which actions can be auto-allowed from scope and data-flow evidence, and which require direct user approval?

### 2. Persistent state is becoming a schedulable systems resource
- **Evidence:** vLLM session-aware KV retention and routing; Google resumable sessions; AWS direct long-term-memory ingestion.
- **Implication:** Serving, workflow state, memory extraction, and resumption should expose lifecycle and locality metadata.
- **Architect's question:** What state is authoritative, what can be recomputed, and what retention policy applies to each class?

### 3. Agent operations are converging on closed-loop evaluation and controlled rollout
- **Evidence:** Red Hat evaluation, canary deployment, rollback, tracing, and showback; Google confirmation flows; AWS ACL diagnostics.
- **Implication:** Production readiness requires evidence linking policy, tool correctness, performance, cost, and deployment transitions.
- **Architect's question:** Can a failed evaluation block promotion and produce a reproducible explanation?
