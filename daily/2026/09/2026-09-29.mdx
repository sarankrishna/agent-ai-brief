## Three signals that should change your mental model

### 1. Agent security is moving below the model boundary

NVIDIA OpenShell 0.1.0 places sandbox, network, credential, audit, and policy controls outside an existing agent workload. Its Gateway, Supervisor, and Sandbox split fleet management, request inspection, and kernel-level workload restrictions. This is a materially different control point from prompt-level safety: the runtime can block a write even when the model or credential would otherwise permit it.

Architectural consequence: treat agent execution as an untrusted workload with an explicit capability boundary, not as an application process with a system prompt. Start with least-privilege network and filesystem policy, separate credentials from the workload, and retain decision logs for review.

[Primary source: NVIDIA, OpenShell 0.1.0](https://developer.nvidia.com/blog/add-runtime-controls-to-ai-agents-with-nvidia-openshell/)

### 2. Generalist computer-use models are converging on one agent loop across interfaces

Hcompany released Holo4-27B and Holo4-35B-A3B, with weights in several formats, trained to combine GUI actions, code execution, MCP, and APIs. Its reported OSWorld 2.0 results show a low-cost open-weight option, but the publisher also notes that harnesses, task subsets, and reference runs differ.

Architectural consequence: the durable abstraction is increasingly the harness, memory, tool policy, and evaluation loop. Model selection should be measured against the interface mix and recovery behavior of the workload, not a single benchmark score.

[Primary source: Hcompany on Hugging Face, Holo4](https://huggingface.co/blog/Hcompany/holo4)

### 3. AI-factory capacity is becoming a control-loop problem

NVIDIA reports a GB300 NVL72 evaluation where DSX MaxLPS increased managed GPUs from 140 to 192 within the same 264.4 kW provisioned budget, with 49.2% higher aggregate throughput. The same test reported a 17% increase in P99 time to first token, so the result is capacity evidence, not a blanket production guarantee.

Architectural consequence: capacity planning must include power telemetry, policy, workload placement, and tail-latency acceptance criteria. Tokens per watt is useful only alongside SLOs and fault-transition behavior.

[Primary source: NVIDIA, DSX MaxLPS evaluation](https://developer.nvidia.com/blog/how-nvidia-dsx-maxlps-maximizes-ai-factory-throughput-and-efficiency/)

### 4. DSX MaxLPS demonstrates power-governed AI-factory headroom

- **Type:** Inference infrastructure and power-management evaluation
- **Evidence:** Tier 1, NVIDIA technical post dated 2026-09-27. The controlled workload used Kimi K2.5 in FP4, 8K input, 1K output, and GB300 NVL72 systems; aggregate throughput rose from 1,084,503 to 1,618,443 tokens/s under the same provisioned budget.
- **Maturity:** Evaluation, not a general production benchmark.
- **Why it matters:** Static peak-power reservations can strand capacity; a policy-governed control loop can trade aggregate headroom against latency and reserves.
- **Architecture read:** Couple GPU power telemetry and placement policy to inference admission control, and validate median, P75, P99, transitions, telemetry failures, and reduced-power operation.
- **What is not proven:** The evaluation is vendor-led and workload-specific. P99 time to first token increased 17%, and results do not establish the same behavior across models, topologies, cooling, or service mixes.
- **Decision:** Discuss.
- **Open loop:** Obtain independent measurements for the target workload mix before using tokens-per-watt gains in capacity or cost forecasts.
- **Source:** [NVIDIA DSX MaxLPS](https://developer.nvidia.com/blog/how-nvidia-dsx-maxlps-maximizes-ai-factory-throughput-and-efficiency/)

## Architecture patterns emerging

### Externalize the capability boundary

**Evidence:** OpenShell and Claude Managed Agents both separate agent reasoning from sandbox execution, credentials, and enforcement.
**Implication:** Design agents as principals operating through a brokered capability system. Prompt instructions remain useful for intent, but authorization belongs in independently enforced runtime policy.
**Architects question:** Can every consequential tool call be attributed, authorized, replayed, and denied without trusting the model explanation?

### Evaluate the agent system, not only the model

**Evidence:** Holo4 emphasizes its harness, memory, shell, trajectories, and interface mix; GitHub describes coding efficiency using steps, tokens, and tool calls; DSX evaluates throughput with latency and power telemetry.
**Implication:** The unit of performance is the complete loop: model, context strategy, tools, retries, sandbox, workload placement, and SLO measurement.
**Architects question:** Which workload-specific traces are required to compare a model or runtime change without confounding harness changes?
