## Three signals that should change your mental model

### 1. Agentic inference is becoming a CPU, memory, and interconnect problem

Arm links agentic workloads to responsive CPU capacity, memory bandwidth, PCIe, and accelerator orchestration. Qualcomm and Amazon announced a multi-generation collaboration on inference silicon and optical connectivity up to 1.6T.

**Architectural consequence:** evaluate agent platforms as heterogeneous systems, not simply model endpoints. Benchmark CPU scheduling, memory movement, accelerator coordination, network congestion, and failure recovery together.

[Arm: AGI CPU and Neoverse CSS N4](https://newsroom.arm.com/news/arm-agi-cpu-neoverse-css-n4-agentic-ai)

### 2. Hardware optimization is moving into a machine-discoverable software supply chain

Arm AI Portal combines model discovery, performance data, deployment workflows, and MCP access. Agents may increasingly select models and runtimes against target hardware constraints rather than relying on manual optimization.

**Architectural consequence:** model registries need executable metadata: supported runtimes, memory, latency, quantization, accuracy evidence, and deployment recipes.

[Arm AI Portal](https://newsroom.arm.com/news/arm-unveils-arm-ai-portal)

### 3. Computer-use agents need hybrid environments, not GUI-only benchmarks

CUA-Universe reports a reproducible VM and data pipeline where agents coordinate GUI and CLI over shared application state. The reported gains are author results, but the design addresses a real evaluation gap.

**Architectural consequence:** agent harnesses should expose both interfaces with explicit state synchronization, provenance, and rollback.

[CUA-Universe paper](https://arxiv.org/abs/2609.05374)

## Architecture patterns emerging

### Heterogeneous agent serving is becoming the baseline

**Evidence:** Arm links agentic workloads to CPU responsiveness, memory bandwidth, PCIe, and accelerator orchestration. Qualcomm and Amazon link inference scale to customized silicon and optical interconnects.

**Implication:** capacity planning should model host CPU, accelerator, memory hierarchy, network fabric, and power as one serving unit. Token throughput alone is insufficient.

**Architect\x27s question:** which parts of the agent loop are latency-sensitive enough to justify local CPU, memory, or fabric specialization, and which can tolerate remote execution?

### Hardware-aware model selection is moving into the agent control plane

**Evidence:** Arm AI Portal exposes machine-discoverable models, performance data, runtimes, and MCP workflows. CUA-Universe exposes a complementary need for agents to choose GUI or CLI actions based on task state.

**Implication:** routing should select not only a model, but an execution path: model, quantization, runtime, hardware target, tool surface, and safety policy. These choices require provenance and regression tests.

**Architect\x27s question:** can a routing decision be reproduced later from immutable model, benchmark, runtime, and hardware metadata?
